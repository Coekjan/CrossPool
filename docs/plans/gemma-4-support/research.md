# Gemma 4 checkpoint and pinned SGLang evidence

CrossPool pins SGLang `0.5.20`, `sglang-kernel` `0.4.7`, and Transformers `5.12.1`. The inspected SGLang wheel's Gemma 4 decoder, both wrappers, Gemma 3 MLP, activation module, and Gemma 4 argument override are byte-identical to their `v0.5.20` sources. The observations below are from public checkpoint metadata and source inspection. Runtime parity, CUDA graph behavior, and cache reclamation require installed-serving evidence. [Project dependencies](../../../pyproject.toml), [Lock file](../../../uv.lock), [PyPI release metadata](https://pypi.org/pypi/sglang/0.5.20/json), [SGLang release](https://github.com/sgl-project/sglang/releases/tag/v0.5.20).

## Decoder integration and parallelism

- Both wrappers construct `Gemma4TextModel` under `language_model`, with the constructor prefix `model.language_model`. Their registered PyTorch child is named `language_model`. Each wrapper has its own `load_weights` method and strips the raw checkpoint's leading `model.` in that method. Filtering the exact raw decoder MLP keys before either original loader preserves the media, PLE, norms, K/V routing and tied head loading. [E2B constructor](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_mm.py#L182-L245), [E2B loader](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_mm.py#L837-L942), [12B constructor](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_unified.py#L138-L190), [12B loader](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_unified.py#L340-L408).
- The pinned Gemma 4 decoder constructs the `gemma4_causal.Gemma4MLP` alias, which points to `Gemma3MLP`. `Gemma3MLP.forward(x)` forms a concatenated `[Gate, Up]`, applies `GeluAndMul(approximate="tanh")`, then projects Down, producing `Down(tanh_gelu(Gate(x)) * Up(x))`. Its CUDA activation delegates to `sgl_kernel.gelu_tanh_and_mul`, which accepts an existing `out` buffer. SGLang `REPLACE` propagates by object identity, so replacing the alias can replace the defining `Gemma3MLP` symbol and other aliases. A model-local `Gemma4DecoderLayer` constructor seam or an upstream Gemma 4-specific MLP factory can isolate the shim. [Gemma 4 alias](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_causal.py#L65-L74), [Pinned MLP](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma3_causal.py#L78-L111), [Pinned activation](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/layers/activation.py#L223-L253), [Kernel output contract](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/kernels/aot/python/sgl_kernel/elementwise.py#L273-L284), [Hook propagation](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/plugins/hook_registry.py#L291-L343).
- The two MLP linears are column-parallel and row-parallel respectively. Down uses `RowParallelLinear`'s default `reduce_results=True`. The dense decoder consumes the completed MLP result before SGLang applies post-FFN RMSNorm, residual addition, E2B PLE, and the layer scalar. E2B's PLE combines a token embedding with the projected input embeddings. The wrapper replaces media token IDs with PAD IDs for the token-side PLE lookup. The 12B decoder takes its fused post-FFN RMSNorm/residual/scalar path for 2D CUDA output. [Row-parallel linear](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/layers/linear.py#L1423-L1478), [Reduction](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/layers/linear.py#L1669-L1692), [Decoder math](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_causal.py#L731-L770), [PLE input](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_mm.py#L625-L668), [PLE projection](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_causal.py#L918-L988).
- Attention uses SGLang's global TP geometry directly in `Gemma4Attention`, with integer sharding of query heads and sharding or replication of KV heads. A first CrossPool deployment can qualify attention TP1 and true FFN TP2 independently. Attention TP2 is consistent with the source head geometry (Full single KV head is replicated) and needs its own installed evidence if admitted. Attention DP with the CrossPool adapter needs a separate row/collective review. [Gemma 4 attention geometry](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_causal.py#L293-L351), [CrossPool topology](../../../src/xpool/integrations/sglang/topology.py).

## Elastic context state

SGLang normalizes the Gemma config's `global_*` metadata into Full geometry and preserves the original head dimensions and counts as `swa_*`. It constructs `SWAKVPool` with separate Full and SWA MHA children and per-component dimensions. K and V remain separate buffers for 12B even though its Full checkpoint has only `k_proj.weight`. The pinned loader loads that projection into both K and V shards. E2B's shared layers point `RadixAttention.layer_id` at the donor, pass no fresh K/V, and suppress cache writes. The pinned pool's `get_hybrid_layer_ids` classifies all 35 text decoder entries, including the 20 E2B aliases. CrossPool's layout must describe the actual factory geometry, so testing 15 donor-layer writes is distinct from testing that the pool describes all 35 entries. [Config normalization](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/utils/hf_transformers/config.py#L211-L245), [Layer classification](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/configs/model_config.py#L2435-L2453), [Pool factory](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/mem_cache/kv_cache_configurator.py#L1730-L1780), [K duplication](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_unified.py#L382-L402), [Donor read path](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_causal.py#L379-L418), [CrossPool layout](../../../src/xpool/integrations/sglang/ecs/state.py).

On CUDA, Gemma 4 defaults to `triton` outside SM100 and `trtllm_mha` on SM100. `kv_cache_builder` rejects SWA-compress models for the separate upstream disaggregated Decode Radix Cache path even when the unified tree is enabled. CrossPool already uses a single installed Instance with its own FFN disaggregation and does not enable SGLang PD disaggregation. The ordinary hybrid Full/SWA path has the shape that CrossPool's layout already supports. Actual descriptor equality and prefix reclamation across the sliding window still require qualification. [Attention backend defaults](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/arg_groups/model_overrides/gemma4.py#L17-L40), [PD cache restriction](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/mem_cache/kv_cache_builder.py#L260-L293), [CrossPool feature rules](../../../src/xpool/integrations/sglang/server_args.py).

## Native multimodal inputs and graph evidence

Google advertises text, image, video, and audio inputs with text output for both checkpoints. E2B uses `Gemma4SGLangProcessor`. 12B uses the Unified subclass and its waveform framing rule of 640 samples per 16 kHz frame. SGLang Chat Completions accepts `image_url`, `video_url`, and `audio_url` parts. It also accepts an `input_audio` part with Base64 WAV or MP3 and converts it to an audio data URI at validation. Native qualification should carry actual media bytes through the pinned server's tokenizer and wrapper. [12B model card](https://huggingface.co/google/gemma-4-12B-it), [E2B model card](https://huggingface.co/google/gemma-4-E2B-it), [Gemma 4 processor](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/multimodal/processors/gemma4.py#L31-L157), [Unified processor](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/multimodal/processors/gemma4_unified.py#L19-L33), [Chat content protocol](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/entrypoints/openai/protocol.py#L585-L658).

The pinned wrapper calls `prepare_attn_masks` on image-bearing EXTEND batches for both classes. This call is independent of the checkpoint's `use_bidirectional_attention` value (`"vision"` for 12B and `null` for E2B). The mask requires a `TritonAttnBackend` and a complete image token span in a single EXTEND. Other backend or split-image chunks can produce causal fallback. Scope image parity to the pinned native SGLang semantics with `--attention-backend triton`, `--chunked-prefill-size -1`, and evidence that the image span remained intact. [Image mask](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_mm.py#L328-L422), [Wrapper forward guard](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/models/gemma4_mm.py#L625-L668).

The native wrappers resolve the default Breakable prefill backend to disabled. Both Gemma architectures are absent from SGLang's multimodal Breakable allowlist. Supplying an explicit prefill backend bypasses that compatibility gate, including when the CrossPool serving harness passes `--cuda-graph-backend-prefill breakable`. Compare Eager with Decode Full and explicitly disabled prefill capture when qualifying these wrappers. [Multimodal Breakable allowlist](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/configs/model_config.py#L2191-L2220), [Explicit backend override](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/arg_groups/cuda_graph_hook.py#L107-L116), [Default disable](https://github.com/sgl-project/sglang/blob/v0.5.20/python/sglang/srt/arg_groups/cuda_graph_hook.py#L318-L343), [CrossPool serving launcher](../../../src/xpool-dev/xkit/serving/sglang/server.py).

Forced Breakable also exposes two concrete source-level risks. The first-PP-rank dummy batch supplies `input_ids` and the multimodal `input_embeds` slot. `_run_forward` passes both to `Gemma4TextModel.forward`, whose argument guard rejects that pair. After a capture-side fix, E2B's `per_layer_inputs` still need a capture/replay handoff. The replay closure copies live embeddings only and its capture kwargs omit this argument. Runtime qualification would need to compare PLE and media outputs from distinct prompts with the eager baseline before Breakable could be admitted.
